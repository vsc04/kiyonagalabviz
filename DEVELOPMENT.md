# Development guide

How to set up, change, test and share kiyonagalabviz. For using the package,
see `README.md`.

## One-time setup

1. Install R (>= 4.1.0) and RStudio.
2. Use prebuilt packages, so nothing needs compiling. Run
   `usethis::edit_r_profile()`, add the line below, save and restart R:

   ```r
   options(pkgType = "binary")
   ```

3. Get the code and install the tools:

   ```bash
   git clone https://github.com/vsc04/kiyonagalabviz.git
   ```

   ```r
   install.packages(c("devtools", "svglite"))
   devtools::install_deps(dependencies = TRUE)
   ```

Repeat step 3's `install` lines after each R upgrade.

## Folder structure

| Path | Contents | Edit by hand? |
|---|---|---|
| `R/` | Package code and `#'` documentation | Yes |
| `tests/testthat/` | Tests | Yes |
| `tools/` | Scripts that regenerate README figures | Yes |
| `man/figures/` | Figures shown in the README | No, regenerate them |
| `man/*.Rd`, `NAMESPACE` | Generated by `devtools::document()` | No |
| `DESCRIPTION` | Package name, version, dependencies | Yes |
| `README.md` | User guide | Yes |

## Everyday workflow

1. Open `kiyonagalabviz.Rproj`, then get the latest version: `git pull`.
2. Edit files in `R/` (and `tests/testthat/` if behaviour changes).
3. Try your changes: `devtools::load_all()`.
4. After changing `#'` comments: `devtools::document()`.
5. Run the tests: `devtools::test()`.
6. Before pushing: `devtools::check()`. Aim for 0 errors and 0 warnings.
7. Commit and push:

   ```bash
   git status
   git add -A
   git commit -m "Short description of the change"
   git push
   ```

## Adding a colour palette

Example: `moss_stone`.

1. **`R/kiyonaga_colors.R`**: add the hex codes with a comment naming the
   source paper. No comma after the last entry in the list.
2. **`R/kiyonaga_palettes.R`**: add the palette (and a `_light` palette for
   shades), plus one line in the `#'` list at the top.
3. **Optional, for `subgroup` shades: `R/kiyonaga_palette_groups.R`**: add an
   entry and update the count and list in the `#'` header.
4. **`tests/testthat/test-palettes.R`**: palette names and colours are
   listed explicitly, so add the new palette:
   - the expected names in the first test (shaded palettes only);
   - the `expected` list in the shade-combination test (shaded palettes only);
   - the hex codes in the last test.
5. **`README.md`**: add the name to the Colours section.
6. **Figure**: regenerate `man/figures/color-palettes.svg` (see below).
7. Run `devtools::document()`, `devtools::test()` and `devtools::check()`.

## Regenerating the palette figure

```r
devtools::load_all()
source("tools/preview_color_palettes.R")
```

The script draws at fixed heights. A new palette with shades needs 1.45 in
more; a new discrete palette (added to the first loop) needs 0.55 in more.
Add the same amount to:

- `height` in the `svglite::svglite()` call;
- the y positions of the title, "Lab palettes" and the first `y <-` line.

Open the SVG afterwards and check that nothing is cut off at the bottom.

## Versions

Change `Version:` in `DESCRIPTION` each time you share an update:
`0.1.1` for small fixes, `0.2.0` for new features such as a palette.

## Troubleshooting

| Problem | Fix |
|---|---|
| `fatal error: 'cstdio' file not found`, or other compile errors | Install the binary version: `install.packages("pkg", type = "binary")` |
| `argument N is empty` in `list()` | Remove the comma after the last list entry |
| `there is no package called ...` | `devtools::install_deps(dependencies = TRUE)` |
| Tests fail after adding a palette | Update `tests/testthat/test-palettes.R` (see above) |
| `check()` note: non-standard top-level file | Delete the file or add it with `usethis::use_build_ignore("file")` |
